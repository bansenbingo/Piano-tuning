# Nexys A7 增加蓝牙远程控制的方案

本文根据 `Reference/A7.md`、`Reference/mic.md` 和当前 Nexys A7 音频工程的接口情况，说明如何为 Nexys A7 增加蓝牙远程操控，以及蓝牙模块的选型要求。

## 1. 结论

可以为 Nexys A7 增加蓝牙系统。最简单、风险最低的实现方式是：

```text
手机/平板
    )) BLE
蓝牙模块（UART 透传）
    -- 3.3 V UART --
Nexys A7 Pmod 接口
    -- FPGA UART 命令解析 --
录音、回放、LED、参数设置等控制逻辑
```

推荐优先选用 **Digilent Pmod BLE（Microchip RN4871）**，或使用同样基于 RN4871 的 3.3 V Pmod/转接板。它将蓝牙协议栈放在模块内部，FPGA 只需要实现 UART 接收、命令解析和状态反馈，不需要在 Artix-7 中实现 BLE 基带、GATT 或射频协议。

> 这里的“远程操控”适合传输开始录音、停止录音、播放、清除、查询状态等低速控制命令。蓝牙模块的 UART 透传并不适合直接传输高质量实时音频；若需要上传完整录音，应继续使用 USB-UART、以太网或 microSD 等更适合的链路。

## 2. 为什么使用 Pmod UART，而不是改动板载 USB

Nexys A7 已有 FT2232HQ 提供 USB-JTAG/USB-UART，但该接口面向电脑连接，不能直接与手机建立蓝牙连接。蓝牙模块应作为一个外部 UART 设备接入 FPGA。

使用 Pmod 的优点如下：

- Pmod JA、JB、JC、JD 都提供 3.3 V 和 GND，适合给低功耗蓝牙模块供电。
- Pmod 的 FPGA 信号可以由用户自行分配为 UART TX/RX，不占用板载麦克风、音频输出和 USB-UART 的固定功能。
- 不需要改动 Nexys A7 主板，也不需要把蓝牙射频信号布线到 FPGA。
- 可以先用 USB-UART 或逻辑分析仪验证 FPGA 命令协议，再接入蓝牙模块。

建议使用 **Pmod JA**，例如将 JA1 作为 FPGA TX、JA2 作为 FPGA RX。`Reference/A7.md` 给出的 JA 引脚是：JA1=`C17`、JA2=`D18`，所在 I/O bank 为 15。也可以使用其他 Pmod，但必须根据实际插接方向和工程约束文件重新核对信号对应关系。

### 推荐连接

| Pmod/模块信号 | Nexys A7 | 说明 |
|---|---|---|
| 模块 VCC | JA 6 或 12（VCC3V3） | 仅连接 3.3 V，不接 5 V |
| 模块 GND | JA 5 或 11（GND） | 必须共地 |
| 模块 TXD | JA2 / FPGA `D18`（RX 输入） | 模块发送到 FPGA |
| 模块 RXD | JA1 / FPGA `C17`（TX 输出） | FPGA 发送到模块 |
| 模块 STATE/STATUS（可选） | 另一个空闲 Pmod I/O | 用于连接状态指示 |

UART 必须交叉连接：`module TXD -> FPGA RX`，`module RXD -> FPGA TX`。若使用带电平转换、丝印为 `VCC/GND/TX/RX` 的成品转接板，应先确认其 TX/RX 的逻辑电平，不能只根据接口名称假定兼容。

## 3. 推荐蓝牙模块和规格要求

### 3.1 首选：Pmod BLE / RN4871

| 项目 | 建议规格 |
|---|---|
| 蓝牙类型 | Bluetooth Low Energy（BLE），推荐 BLE 4.2 或更高 |
| 核心模块 | Microchip RN4871，或功能等效的 BLE UART 模块 |
| FPGA 连接 | 3.3 V CMOS UART，TXD/RXD |
| 供电 | 3.3 V，模块端必须能接受 Pmod 的 3.3 V；按具体数据手册核对峰值电流 |
| 主机接口 | UART，初始配置优先选择 115200 8-N-1；最终以模块固件默认值为准 |
| 工作方式 | BLE GATT 服务/特征或模块提供的 UART 透传服务 |
| 手机兼容性 | Android、iOS 均可，使用支持 BLE UART 的 App 或自写 App |
| 额外信号 | RESET、WAKE/PIO、连接状态输出可选 |
| 射频 | 2.4 GHz，模块应带天线或板载天线，并有明确的认证/布局说明 |

RN4871 内置 BLE 协议栈，FPGA 不需要处理复杂的无线协议。Pmod BLE 还具有适合教学和原型开发的标准 Pmod 机械接口，避免了裸模块的天线、供电和焊接问题。因此它是本项目最合适的第一选择。

### 3.2 可选：nRF52832 或同类 BLE UART 模块

如果买不到 Pmod BLE，可以选择带 UART 透传固件的 nRF52832 模块。要求模块已经提供可用的 BLE UART 服务，而不是只有空白芯片或需要用户自行开发 nRF5 SDK 固件。模块必须明确支持：

- 3.3 V 供电和 3.3 V UART I/O；
- BLE GATT UART 透传；
- 可配置波特率；
- 硬件复位脚或可通过电源复位；
- 2.4 GHz 天线及其布局要求。

### 3.3 不建议作为首选：HC-05/HC-06 和裸 ESP32

- HC-05/HC-06 主要是 Bluetooth Classic SPP，不是 BLE。Android 通常较容易使用，但 iOS 对通用 SPP 的支持不适合作为跨平台方案。
- 许多 HC-05 成品板标注“5 V”，但这通常只表示板载稳压器的输入，RX 逻辑是否耐 5 V 必须查看具体电路；直接把不确定的信号接入 FPGA 有损坏风险。
- ESP32/ESP32-C3 可以实现 BLE，但若只用作 UART 蓝牙桥接，会引入固件、启动模式、功耗和调试工作；只有在还需要 Wi-Fi、复杂协议或本地应用逻辑时才值得采用。

## 4. FPGA 端的实现建议

### 4.1 UART 接收和发送

FPGA 使用 `CLK100MHZ`（`E3`）作为系统时钟。UART 逻辑在 100 MHz 时钟域内产生波特率计时器，接收端采用 8 倍或 16 倍过采样，并对外部 RXD 使用两级同步触发器。

推荐初始配置：

```text
波特率：115200 bit/s
数据位：8
校验：无
停止位：1
流控：无
```

115200 bit/s 对录音开始/停止和状态查询等命令有很大余量。即使改用 9600 bit/s，也能满足控制用途；调试阶段优先使用 115200 bit/s。

不要让异步蓝牙 RXD 直接驱动控制状态机。应采用：

1. RXD 两级同步；
2. UART 接收器组装完整字节并产生 `rx_valid` 脉冲；
3. 命令解析器接收字节并检查帧头、长度和校验；
4. 只有完整且校验正确的帧才能产生一次控制脉冲。

### 4.2 建议的控制帧

建议使用二进制短帧，避免蓝牙连接受到干扰时把半条字符串当成有效命令：

```text
0xAA | CMD | LEN | PAYLOAD... | CHECKSUM
```

其中 `CHECKSUM` 可定义为 `CMD + LEN + PAYLOAD` 的低 8 位。可先实现以下命令：

| CMD | 功能 | 说明 |
|---|---|---|
| `0x01` | 开始录音 | 等效于录音控制开关 |
| `0x02` | 停止录音 | 提前结束本次录音 |
| `0x03` | 播放录音 | 等效于回放控制开关 |
| `0x04` | 清除录音 | 清零有效样本数/状态 |
| `0x10` | 查询状态 | 返回空闲、录音、播放、错误等状态 |
| `0x11` | 设置参数 | 预留采样率、音量或播放模式参数 |

FPGA 返回帧应至少包含 `ACK/ERROR`、当前状态和错误码。录音与播放状态机应保留原有的互锁关系，蓝牙命令只产生与按键/开关等价的内部控制事件，不应绕过复位、缓存边界和音频输出保护逻辑。

### 4.3 与当前音频工程的关系

当前资料中的设计使用 100 MHz 系统时钟、约 2.5 MHz PDM 时钟、128 位抽取和片上录音缓存，并通过 Nexys A7 的开漏 PWM 音频输出回放。蓝牙控制只需要连接到上层控制状态机：

- 不改变 `M_CLK`、`M_DATA` 和 `M_LRSEL` 的 PDM 时序；
- 不把 UART 时钟当作音频采样时钟；
- 不改变 `AUD_PWM` 的开漏驱动要求；
- 给录音/播放计数器增加边界检查和命令互斥；
- 蓝牙断开时保持当前安全状态，不能因为 RXD 悬空而反复触发录音。

## 5. 手机端和系统工作流程

1. Nexys A7 上电，FPGA 初始化 UART 和音频状态机。
2. 蓝牙模块上电并广播 BLE 服务。
3. 手机 App 扫描并连接模块，发现 UART 写入/通知特征。
4. 手机向模块写入控制帧，模块通过 UART 转发给 FPGA。
5. FPGA 返回 ACK 或状态帧，模块通过 BLE 通知手机。
6. 手机显示连接、录音、播放和错误状态。

调试时可先使用通用 BLE UART 工具验证模块，再接入自写 App。第一次联调只发送 `查询状态` 和 `LED 测试`，确认 UART 交叉连接、波特率和电平无误后，再接入录音/播放控制。

## 6. 电气和安全检查

- Pmod 逻辑应按 3.3 V LVCMOS 设计；FPGA I/O 不接受 5 V 输入。
- 模块电源电流必须由实际模块数据手册确认。Pmod 的“可提供电流”不是允许所有模块无限制取电的保证，射频发射峰值电流尤其需要留余量。
- 模块和 Nexys A7 必须共地，TX/RX 必须交叉连接。
- 不要同时把同一 Pmod 引脚连接到两个输出设备，避免总线争用。
- 蓝牙模块的天线区域不要贴近金属、排线或 FPGA 大面积高速信号；按模块厂商的天线禁布区安装。
- 上电前用万用表确认 VCC 与 GND 没有短路，再接入开发板。
- 如果使用带 5 V 供电标识的第三方模块，必须核查其 UART 电平转换电路；不满足 3.3 V I/O 要求时应增加可靠的电平转换器。

## 7. 推荐采购清单

### 最推荐的组合

- 1 个 Digilent **Pmod BLE**（RN4871）；
- 1 个标准 Pmod 排针/排线；
- 1 个支持 BLE UART 的手机 App，或自定义 Android/iOS App；
- FPGA 工程中的 UART、命令帧解析和状态反馈模块。

### 购买裸模块时的最低要求

采购页面和数据手册都应明确写出：`BLE`、`3.3 V UART`、`3.3 V supply`、可配置 UART 波特率、板载/外接天线和 BLE UART 透传服务。只写“Bluetooth 4.0”而不说明 BLE、逻辑电平和 UART 参数的模块不建议采购。

## 8. 最终建议

对于当前 Nexys A7 音频录音工程，选择 **Pmod BLE（RN4871，3.3 V UART，BLE 4.2 级别的模块）**，通过 **Pmod JA 的两根普通数字 I/O** 接入，是实现手机远程录音/播放控制的最小改动方案。第一版只实现控制和状态回传，不通过蓝牙传输 PCM 音频；待控制链路稳定后，再根据数据量选择 USB-UART、以太网或 microSD 处理录音文件传输。

实际购买前仍应以具体批次的模块数据手册核对供电电流、默认波特率、UART 电平和 BLE 服务 UUID；不同厂家的“RN4871 模块”可能只提供芯片级封装或不同的引脚定义。
