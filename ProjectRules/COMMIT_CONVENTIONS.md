# 提交规范

本规范适用于 `Piano-tuning` 工程的所有文件、所有由 OpenCode 创建的提交以及所有现在或将来创建的受版本管理分支。提交前必须检查当前分支、提交主题编号和本文件中的编号顺序。本文件是规范的唯一专门维护入口；用户可以随时修改或补充它，后续 OpenCode 提交必须以修改后的内容为准。

## 1. 提交主题格式

每个提交主题必须以版本编号开头，后接简短的英文动作描述：

```text
主版本.主题编号 [可选的.修订编号] 简短描述
```

示例：

```text
0.6 Add commit conventions
1.6 Add Bluetooth control RTL
1.4.3 Fix UART upload timeout
```

提交主题不能省略版本编号。版本编号之后至少应有一个空格和描述，描述应准确说明本次提交的主要内容。

## 2. 分支与编号归属

| 分支 | 编号前缀 | 当前最新编号 | 后续编号 |
|---|---|---:|---|
| `main` | `0.x`、`0.x.y` | `0.6` | 新主题使用 `0.7`、`0.8`；旧主题修订使用对应的 `0.x.y` |
| `sandbox-audio-upload` | `1.x`、`1.x.y` | `1.6` | 新主题使用 `1.7`、`1.8`；旧主题修订使用对应的 `1.x.y` |
| `audio-waveform-analysis` | `2.x`、`2.x.y` | `2.4` | 新增或删除功能使用下一个 `2.x`；优化已有功能使用对应的 `2.x.y` |

- `0.x` 和 `0.x.y` 只能提交到 `main`。
- `1.x` 和 `1.x.y` 只能提交到 `sandbox-audio-upload`。
- `2.x` 和 `2.x.y` 只能提交到 `audio-waveform-analysis`。
- 从 `main` 创建的新分支继承 `0.x` 前缀；从 `sandbox-audio-upload` 创建的新分支继承 `1.x` 前缀。新分支不得自行改变继承的主版本前缀。
- 如果未来增加新的长期分支，必须在本文件中记录该分支的版本前缀和当前最新编号。普通新分支继承其创建来源分支的版本前缀；提交钩子会根据分支历史自动检查来源为 `main` 或 `sandbox-audio-upload` 的新分支。
- `audio-waveform-analysis` 是音频波形分析 Python 工程的长期分支，使用 `2.x` 主版本前缀。新增或删除功能递增主题编号（`2.0`、`2.1`、`2.2`……）；对已有功能进行优化时，在对应主题编号后追加修订编号（如 `2.1.1`）。
- 不同主题顺延中间编号。例如当前主题为 `1.6`，新主题使用 `1.7`，再下一个新主题使用 `1.8`。
- 对已经完成的主题进行修改时，在原主题编号后追加修订编号。例如对 `1.4` 的第三次修改使用 `1.4.3`，而不是占用新的主题编号 `1.9`。
- 同一主题的修订编号从 `1` 开始，并按该主题的已有修订次数递增。
- 不得复用已经使用过的编号，不得跳过当前分支的最新编号，除非用户明确指定。

## 3. OpenCode 提交流程

每次由 OpenCode 提交前必须：

1. 检查 `git status`，确认没有误包含用户或其他协作者的改动。
2. 检查当前分支，确认版本前缀与分支匹配。
3. 查看当前分支最近提交，确定新主题编号或旧主题修订编号。
4. 只暂存本次任务涉及的文件。
5. 使用符合本规范的提交主题，并运行 `git diff --check`。
6. 提交后检查提交主题、分支状态和远程同步状态。

启用仓库提交钩子：

```sh
git config core.hooksPath .githooks
```

提交钩子会拒绝没有版本编号的提交，也会拒绝版本前缀与当前分支或其继承来源不匹配的提交。钩子是自动检查，不能替代提交前的编号顺序检查。若新分支无法从 `main` 或 `sandbox-audio-upload` 判断来源，必须先在本文件和 `.githooks/commit-msg` 中补充该分支规则。

## 4. 修改和补充规范

用户可以随时修改或补充 `ProjectRules/COMMIT_CONVENTIONS.md`，新增分支、编号、描述格式或例外规则。修改规范本身也必须遵守本规范：

- 在 `main` 修改规范，使用下一个 `0.x` 主题编号。
- 在 `sandbox-audio-upload` 修改规范，使用下一个 `1.x` 主题编号。
- 在 `audio-waveform-analysis` 修改规范，新增或删除功能使用下一个 `2.x` 主题编号；已有功能优化使用对应的 `2.x.y` 修订编号。
- 同一规范主题的后续修改，使用该主题的修订编号，例如 `0.9.1` 或 `1.9.1`。
- 如果规范修改影响自动校验，必须同步修改 `.githooks/commit-msg`，并在提交前验证新旧分支行为。
- OpenCode 后续提交必须先读取修改后的本文件，再按最新规则工作。

## 5. 提交示例

```text
0.9 Add project rules
0.8.1 Fix convention wording
1.9 Add remote control UART module
1.4.3 Fix upload timeout handling
```
